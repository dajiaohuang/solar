# Solar Atlas audit — 2026-09-22

This audit reviewed the open contribution queue, current product direction, dependency security, backend startup and numerical contracts, browser storage and rendering, CI gates, immutable data delivery and the published preview. It repairs observed defects without claiming that the future full-backend/native roadmap is complete.

## Contribution decisions and direction

At the start of the audit the repository had no open issues and one open pull request, [#179](https://github.com/dajiaohuang/solar/pull/179). Its original Horizons type 21 primary ephemerides for Altjira (`20148780`) and Mbabamwanawaresa (`20184314`) match the accepted source-backed coverage direction. Review checked the two original files, two preview excerpts, frozen provenance, dependencies and the distinction between a primary, companion and system center. All 63 focused kernel/pool/preset tests passed and the submitted head had successful Web and native CI. The reviewed head `86a7fe40d9e9a9beff817dd60e931b20ddc70ea4` was merged as `6525dfc6babf4f0e6d1c650fa84028dd4104a88a`.

The accepted architecture remains independent Web, Android and iOS clients with one Go scientific/data backend. GitHub Pages is a curated preview; its package limits do not narrow the full-product coverage target. The [roadmap](../ROADMAP.md) now separates current evidence from future delivery priorities. No issue was closed merely to hide an unfinished roadmap item.

## Findings and repairs

| Area | Observed failure | Repair and verification |
| --- | --- | --- |
| Dependency security | The previous lockfile reported three moderate findings: Vitest/mocker path traversal and an fflate malformed-ZIP64 infinite loop. The local Go 1.26.3 standard library had eight reachable vulnerability findings. | Upgrade Vitest to 4.1.11, fflate to 0.8.3 and the project Go minimum to 1.26.8. CI selects Go from `go.mod`; npm audit and pinned govulncheck now run in the required quality workflow. Both scans report zero findings on the audited versions. |
| Backend availability | A configured catalog or inventory could fail to load while startup continued; an empty catalog path could also reach a nil dereference. | Reject invalid configured inputs before starting HTTP and close any partially loaded catalog. Regression cases cover empty/missing/malformed catalogs and inventories. Valid manifests with absent kernels still return explicit `kernel-not-packaged` states. |
| Browser cache bounds | Pruning only every 32 writes allowed a concurrent burst to exceed the global byte budget. | Reserve incoming bytes, replace a matching key and evict LRU records within one IndexedDB write transaction. A real IndexedDB regression issues three concurrent 6 MiB writes into a 16 MiB budget and verifies that only two records remain. |
| Narrow layouts | A fixed 320 px root minimum overflowed a 320 px WebKit viewport when its scrollbar left only 312 px available. | Let the root shrink to the available width. The regression asserts that scroll width never exceeds client width; Linux Firefox can legitimately report a smaller scroll width when a classic scrollbar occupies the root box. |
| Browser quality | The previous scheduled matrix failed in Firefox without WebGL2 and exposed WebKit layout/storage differences. Browser results were not part of the merge gate. | Run independent Chromium desktop/mobile, Firefox and WebKit jobs on every applicable PR. Linux Firefox uses Xvfb with software graphics. Any matrix failure now fails the stable required quality check. |
| Asynchronous browser assertions | Tests could choose mobile navigation before desktop navigation mounted, navigate away before a PNG export finished, assert before downloads began, or inspect a discarded GPU drawing buffer. A reference-state test depended on a transient loading state. | Wait for visible navigation, the completed download and observable requests; capture the renderer through its existing export event; give the missing-reference test an explicitly missing fixture. These changes retain assertions against actual output. |

The cache transaction scans existing records on each write and retains only their metadata during eviction. This trades additional cursor work for an enforced persistent byte bound; it is not a claim of faster bulk-cache throughput. Scientific solver code and scientific tolerances were not changed by these repairs.

## Remaining delivery boundaries

1. **Public full product:** no public full-Web backend endpoint was available for this audit. Local HTTP and CI loopback HTTPS do not prove public deployment, recovery or production load behavior. Full inventory-backed operations require their separately pinned inventory artifacts.
2. **Native release:** simulator/emulator tests cover the current-state vertical slice. Full feature parity, physical-device behavior and signed store-ready releases remain outstanding.
3. **Performance:** the build still reports a shared JavaScript chunk above its 600 kB warning threshold. No threshold was raised to hide it. Cold-start and concurrent-load improvements require measured workloads; this audit does not infer them from unit tests.
4. **Scientific scope:** missing original sources remain missing. No companion or system-center state is manufactured from a new primary, and no approximate model is relabeled exact. Heavy client analyses and broader source delivery remain explicit roadmap work.
