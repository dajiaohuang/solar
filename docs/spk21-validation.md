# SPK type 21 validation and TNO center semantics

This is an evaluator-validation record, not a claim of observational accuracy,
all-body completeness, or navigation suitability. No CSPICE library is shipped
with the app; the C oracle is an independent developer test tool.

## Authoritative implementation

The on-disk layout and recurrence were checked against NAIF N0067
`spkw21.c`, `spkr21.c` and `spke21.c`. A segment ends with `MAXDIM, N`.
Each stored line has `4 * MAXDIM + 11` words; its first word is the reference
epoch. The leading dimension in SPKE21's input is an SPKR21 workspace prefix,
not a stored line word. N record-final epochs are followed by `floor(N/100)`
directory entries. Exact boundaries select the first final epoch at or after ET.

The reader supports dimensions 15–25, validates active step sizes, integration
orders, finite records, exact layout and directory/epoch consistency, and
preserves last-matching-segment precedence. Cropping retains complete original
lines and reconstructs only the descriptor/epoch directory; there is no fit.

Primary documentation: [SPK required reading](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/spk.html),
[SPKE21](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/FORTRAN/spicelib/spke21.html),
[SPKR21](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/FORTRAN/spicelib/spkr21.html).

## Independent evidence

- `spk21-synthetic.bsp/json`: official SPKW21 creates six synthetic segments
  with dimensions 15, 20 and 25, and 1, 99, 100, 101, 200 and 201 records.
  Official CSPICE supplies 175 six-component state samples at endpoints,
  directory/record boundaries and deterministic interior dates. These deliberately
  synthetic polynomials test mechanics, not physical orbits.
- `spk21-horizons-{eris,haumea,makemake}.bsp` and the corresponding JSON samples:
  87 samples each, comparing cropped original type 21 records against CSPICE
  evaluation of the unmodified API source over 2020–2031 TDB. J2000 heliocentric
  and ECLIPJ2000 barycentric states are checked. These three fixtures describe
  small-body solution points, not verified primary centers.
- `spk21-{eris,haumea}-primary.json`: 61 samples each, including both distribution
  endpoints, generated by CSPICE from the full original TNO satellite delivery.
  Tests compare the packaged type 2 primary offset plus type 21 system trajectory
  through the DE440 Sun center chain, including explicit rejection outside coverage.
- Big-endian, overlapping-segment precedence, original coefficient-byte retention,
  nested crop boundaries, malformed records and lazy complete-chain selection
  have additional deterministic tests.

Synthetic parity was exact at the 175 recorded samples in the initial local
comparison. The three Horizons fixture comparisons differed by at most
`1.91e-6 km` in a position component and `8.89e-16 km/s` in a velocity component.
Tests allow `1e-5 km` and `1e-13 km/s` for real-source component comparisons.
These are numerical implementation differences against the same source, **not**
physical orbit uncertainties or accuracy guarantees.

Full source, API response and fixture hashes are recorded in
[the provenance manifest](../tests/fixtures/spk21-provenance.json).
The API solution headers are retained there; a later request may return a new
solution and must produce a new validation record rather than silently replacing it.

## Primary versus system

The two runtime additions use these original JPL deliveries:

| Named body | Primary ID | System ID | Source solution | Pack interval (TDB) |
|---|---|---|---|---|
| Eris | 920136199 | 20136199 | SOLN001 + JPL#80 | 2020-01-01–2030-01-02 |
| Haumea | 920136108 | 20136108 | corrected SOLN001 v001b + JPL#110 | 2020-01-01–2030-01-02 |

[Eris original kernel](https://ssd.jpl.nasa.gov/ftp/eph/satellites/bsp/tnosat_v001_20136199_jpl080_20220908.bsp)
and [Haumea corrected original kernel](https://ssd.jpl.nasa.gov/ftp/eph/satellites/bsp/tnosat_v001b_20136108_jpl110_20221014.bsp)
contain their own system trajectories. The app retains those with their primary
offsets, rather than mixing them with the independently newer Horizons fixtures.
The original Eris model assumes zero Dysnomia GM; this does not establish that
the satellite is massless. Source-model limitations persist in the packaged states.
The satellite components themselves are not added as selectable bodies in this batch.

Makemake's downloaded JPL#130 small-body solution validates the general reader,
but no resolved primary-center offset has been verified here. Its named-body
runtime state therefore remains explicitly approximate. There is no invented
offset, mass or orbital phase. This unresolved identity/geometry distinction
remains part of the all-body backlog.

## Reproduction

Normal unit/scientific tests read checked-in fixtures offline:

```sh
npm run test:scientific
npm run data:ephemerides
```

The second command is explicitly online when verified published/cached crops
are unavailable. The runtime pack is not the same as the three Horizons test
fixtures. See the [physical contract](./physical-ephemerides.md) for cache and
explicit-refresh controls.

To regenerate oracle output, download the official
[Linux GCC 64-bit CSPICE package](https://naif.jpl.nasa.gov/pub/naif/toolkit/C/PC_Linux_GCC_64bit/packages/cspice.tar.Z)
into a developer directory and extract it there. N0067 package SHA-256:
`60a95b51a6472f1afe7e40d77ebdee43c12bb5b8823676ccc74692ddfede06ce`.
With an existing C compiler, compile the two [reference generators](../scripts/reference/spk21-oracle.c)
and [real-source generator](../scripts/reference/spk-state-oracle.c):

```sh
cc -O2 -I CSPICE_DIR/include scripts/reference/spk21-oracle.c CSPICE_DIR/lib/cspice.a -lm -o spk21-oracle
cc -O2 -I CSPICE_DIR/include scripts/reference/spk-state-oracle.c CSPICE_DIR/lib/cspice.a -lm -o spk-state-oracle
./spk21-oracle NEW_SYNTHETIC.bsp NEW_SYNTHETIC.json
./spk-state-oracle 920136199 631108800 946814400 NEW_ERIS.json ORIGINAL_ERIS.bsp DE440_CORE.bsp
./spk-state-oracle 920136108 631108800 946814400 NEW_HAUMEA.json ORIGINAL_HAUMEA.bsp DE440_CORE.bsp
```

Replace uppercase paths with actual local paths. Output paths must not exist.
Windows validation used an already-installed WSL Ubuntu/GCC and the same official
static library; this is not a new app dependency. For Horizons fixtures, use
the [official SPK API contract](https://ssd-api.jpl.nasa.gov/doc/horizons.html)
and [bounded retrieval helper](../scripts/lib/horizons-spk.mjs), serialize requests,
retain raw sources/responses, then crop via [crop-spk](../scripts/crop-spk.mjs).
Use targets 20136199, 20136108 and 20136472 and ET bounds 631108800–978264000
with the real-source generator. The source cache can be captured with
[record-spk21-provenance](../scripts/reference/record-spk21-provenance.mjs).
